# Language foundation (English and Arabic)

> **English only from 2026-10-22** ([product decision](product-decisions.md#english-only-decided-2026-10-22)): new text goes in the English catalogue only, and `npm run check:i18n` checks English alone. The Arabic catalogue, the preview and the right-to-left rules below are frozen: kept, not updated, and not required for new work.

Status: foundation built 2026-10-16 ([product decision](product-decisions.md#design-and-language-going-forward-decided-2026-10-16), [product vision](product-vision.md) item 2). Every feature built from now on uses translation catalogues from the start. Existing screens are still English and are translated in a later, separate pass.

## Pieces

| Piece                  | Where                                                                            |
| ---------------------- | -------------------------------------------------------------------------------- |
| Languages and settings | `apps/crm/src/i18n/languages.js` (`en` default, `ar` right to left)              |
| Lookup and plurals     | `apps/crm/src/i18n/translate.js` (pure, unit-tested)                             |
| Formatters             | `apps/crm/src/i18n/format.js`                                                    |
| React                  | `LanguageProvider` (mounted in `apps/crm/src/main.jsx`) and `useI18n()`          |
| Catalogues             | `apps/crm/src/i18n/catalogs/<language>/<namespace>.js`, registered in `index.js` |
| Logical CSS utilities  | `apps/crm/src/styles/i18n.css` (imported last)                                   |
| Check                  | `npm run check:i18n` (also in CI)                                                |

No dependency was added.

## Using it in a feature

```jsx
import { useI18n } from '../../i18n/useI18n.js';

function DealSummary({ deal }) {
  const { t, format } = useI18n();
  return <p>{t('deals.summary', { name: deal.name, price: format.money(deal.priceFils) })}</p>;
}
```

`useI18n()` returns `t(key, vars)`, `language`, `locale`, `dir`, `format`, `languages` (the choices on offer) and `setLanguage`.

## Adding a namespace and keys

1. Create `apps/crm/src/i18n/catalogs/en/<namespace>.js` and `ar/<namespace>.js`, each `export default { 'some.key': 'Text' }`. Keep each file within 150 lines; split a large feature into several namespaces.
2. Register both in `apps/crm/src/i18n/catalogs/index.js`.
3. Reference keys as `<namespace>.<key>`, for example `t('profile.language.title')`.
4. Run `npm run check:i18n`. It fails when namespaces or keys differ, a value is empty, plural forms do not match a language, `{placeholders}` differ, or a file is not registered.

Rules: interpolate with `{name}` (numbers are formatted for the language). Never concatenate translated fragments; give the whole sentence one key. A missing Arabic key shows English and warns in the development console; an unknown key shows nothing, never the raw key. Server error messages are still English, so show a translated message for errors the feature expects.

## Plurals

Give an object keyed by [`Intl.PluralRules`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules) categories and pass `count`:

```js
// en
'sessions.count': { one: '{count} session', other: '{count} sessions' },
// ar: all six forms are required
'sessions.count': { zero: 'لا جلسات', one: 'جلسة واحدة', two: 'جلستان', few: '{count} جلسات', many: '{count} جلسة', other: '{count} جلسة' },
```

## Formatting

`format.date`, `time`, `dateTime`, `number`, `percent(bp)` and `money(fils)` follow the language and always use the **Asia/Dubai** calendar. A `YYYY-MM-DD` day is never shifted by time zone. Missing values show a dash.

- **Western digits for Arabic (decision 2026-10-16):** Arabic uses `ar-AE-u-nu-latn`, so prices, unit numbers, phone numbers and dates use 0-9 and stay unambiguous across languages and copy-paste.
- **Money stays in whole fils.** `money` passes the exact decimal text from `apps/crm/src/lib/finance/money.js` to `Intl`, never a float. English output is exactly `formatAed` and `formatPercent`, so existing figures do not change. Arabic shows, for example, `2,450,000.50 د.إ.`.
- Times use the 24-hour clock in both languages, matching the existing `14:05`.

## Right to left

`LanguageProvider` sets `<html lang dir>` (`dir="rtl"` for Arabic). Arabic text uses the device's Arabic system fonts (`Geeza Pro`, `Segoe UI`, `Noto Sans Arabic`, …) only when `lang="ar"`; nothing is downloaded, and letter spacing is reset because cursive Arabic must not be spaced.

For new CSS:

- Use logical properties: `margin-inline-start`, `padding-inline`, `inset-inline-start`, `border-inline-end`, `text-align: start`, `inline-size`/`block-size`. Avoid `left`/`right` unless something is truly physical.
- Mirror directional icons (arrows, chevrons, back/next) and time axes in charts with `.u-mirror-rtl`; do not mirror icons that mean the same both ways (check, search, clocks).
- Wrap phone numbers, emails, IDs and unit numbers in `.u-ltr` so their order stays left to right inside Arabic text.
- Flex and grid follow `dir` automatically; check both directions at 390px and 1280px.

Existing CSS uses physical properties and is converted in the translation pass, not now.

## Choosing a language

- **Connected mode:** each member's `language` (`en` | `ar`, default `en`) is stored on their account (`crm_users.language`, migration 0021) and returned in the session, sign-in and `GET /auth/account` payloads. `PUT /api/crm/auth/account/language` with `{"language":"ar"}` changes only the caller's own language: strict allowlist, unknown fields refused, CSRF and origin checks, no member ID in the route, so no Admin or Super Admin can change anyone else's. It does not bump the account version (an unsaved details draft is kept) and logs the existing `profile_updated` account event, never the value. Team directory payloads do not include members' languages.
- **Before sign-in and in the frozen demo:** the browser's saved choice (`localStorage` key `kws-crm-language`, read and written inside try/catch) or English. Signing in copies the account's choice there. The demo has no language control and stays English.
- **My profile → Language:** cards for English and العربية, saved as soon as one is chosen, with saving, saved and error (Try again) states.

## Field guidance

Packet Q1 adds translated field hints for connected members.

- The preference is `crm_users.guidance_enabled` (migration 0026), default `true`, exposed as `guidanceEnabled` in session, sign-in and `GET /auth/account` payloads. Team directory rows omit it.
- `PUT /api/crm/auth/account/guidance` with `{"enabled":false}` changes only the caller's own preference: strict boolean body, unknown fields refused, CSRF and origin checks. It does not bump the account version, and logs the redacted `profile_updated` event only when the value changes.
- `FieldHint` (`apps/crm/src/components/ui/FieldHint.jsx`) shows a hint while an untouched field is focused, hides it after typing and reopens it from the information button. The button stays available when automatic hints are off, so every mode keeps discoverable help.
- Hint text lives in the `fieldHints` namespace: `fieldHints.clients.<field>`, `fieldHints.properties.<field>`, `fieldHints.deals.<field>` and `fieldHints.payments.<field>`. `apps/crm/src/i18n/fieldHintKeys.js` lists the record fields that carry guidance, so other fields never request missing text.
- Current coverage: Client phone, preferred channel, buy/rent and maximum budget; Property price, price basis, ready/off-plan, permit reference and minimum stay; Deal value, fee basis, fee rate, fixed fee and partner share; Payment deal, receipt date, amount and reference.
- **My profile → Field guidance** holds the switch with saving, saved and error (Try again) states.

Automatic hints require the connected server preference. The focused browser check covers focus, typing, the icon, the preference off/on, dark mode and a 390px viewport; Arabic text and catalogue parity are covered by unit tests and `npm run check:i18n`.

## Preview flag

Until the translation pass, **Arabic is a preview**. It is offered, and applied, only when the build sets `VITE_I18N_PREVIEW=true` (see `.env.example`); it is labelled "Preview — most screens are still in English". With the flag off, the Language section is hidden and everyone sees English whatever was saved, so real users never land in a half-translated right-to-left app. The connected browser harness turns the flag on for `apps/crm/tests/server-browser/language.spec.js`.

## Later translation pass

Screen by screen: move each screen's text into its own namespace, convert its CSS to logical properties, mirror directional icons and charts, check both directions in both themes, then remove the preview flag once every screen is done.
