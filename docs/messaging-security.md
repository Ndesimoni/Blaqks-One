# Messaging security review

Separate security review of packet X0, the [messaging design](messaging-design.md), and the X1 channel connections registry. Written 2026-10-20 against the `feature/connected-crm` working tree, as required by the [messaging integrations plan](messaging-integrations-plan.md) ("the security review lists no open high-severity issues"). Review only: no provider was contacted and no real credential was used.

**Outcome:** two High findings (SEC-1, SEC-2) were design gaps. Both are now closed in the design text, so no High issue remains open and the owner approved X0 on 2026-10-20 with the recommended decisions in [§13 of the design](messaging-design.md#13-open-decisions). X1 holds only synthetic stub data; its code findings are fixed except where a row says which later packet carries the work.

## Findings

| ID     | Severity | Area                             | Risk                                                                                                                                                                                                                                                                            | Resolution                                                                                                                                                                                                                                                                                                                                                      | Status                                                                              |
| ------ | -------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| SEC-1  | High     | Design §3, §7, §8; X1 connect    | The external account ID was whatever the Admin typed. Company B could register company A's Page, number or mailbox first; Meta signs every webhook with one app secret, so A's client messages would route into B's Inbox. The 409 also revealed which accounts were connected. | Real adapters derive the account ID from the provider using the credential, store it canonically (E.164 phone, lower-case email) and never accept it from the browser. Reconnect proves the new credential opens the same stored account. A distinct "already connected" answer is acceptable only after ownership is proven and never names the other company. | Design fixed; enforced in W1, E1, S1                                                |
| SEC-2  | High     | Design §5                        | If the worker crashes or its call outlives the lease after the provider accepted the message, the job is claimed again and the client receives it twice. Providers offer no send idempotency keys.                                                                              | An in-flight attempt row commits before the provider call; an expired lease with an in-flight attempt becomes `unknown` and is never re-claimed. The provider timeout is shorter than the lease. Idempotency is documented as internal only.                                                                                                                    | Built in X2 (outbox attempts, lease sweep, tests in `outbox/lease_tests.rs`)        |
| SEC-3  | Medium   | Design §7                        | Asynchronous processing had nowhere to keep a verified payload; unknown connections wrote receipts before any signature check, so anyone could fill the table.                                                                                                                  | Verified events are staged in an encrypted, short-lived `integrations` row purged with the receipts. Unauthenticated requests write nothing and only increment a counter.                                                                                                                                                                                       | Built in X2 (verified-only receipts, sealed staging, `tests/api/webhooks.test.mjs`) |
| SEC-4  | Medium   | Design §7                        | Per-provider verification gaps: Twilio signed URL behind proxies, key lookup before verification, no event ID on status callbacks, no timestamp; Microsoft `clientState` is a bearer secret; Google audience/issuer checks; Meta verify handshake.                              | Provider rules written out in §7, each with a forged and a replayed fixture test.                                                                                                                                                                                                                                                                               | Design fixed; X2, W1, E1, S1                                                        |
| SEC-5  | Medium   | Design §8; `config_messaging.rs` | Only one key was loaded, so rotation would make every older credential unreadable.                                                                                                                                                                                              | A keyring: the current key plus retired keys selected by `credential_key_version`; startup fails if a stored version has no key.                                                                                                                                                                                                                                | Design fixed; built in W1 (first decrypt)                                           |
| SEC-6  | Medium   | Design §3, §11; X1 email         | Email is per person, but an Admin connecting staff mailboxes would hold their credentials, and a departed member's mailbox would keep syncing.                                                                                                                                  | Each member connects their own mailbox through OAuth; the Admin approves. Archiving or deactivating a member disconnects their connections in the same transaction. X1 lets an Admin connect only their own mailbox.                                                                                                                                            | Design fixed; E1                                                                    |
| SEC-7  | Medium   | Design §8, §12                   | No OAuth flow was specified, and disconnect did not revoke the token at the provider.                                                                                                                                                                                           | §8 adds redirect allowlist, `state` + PKCE, sealed refresh tokens and provider revocation on disconnect (best effort, retried through the outbox).                                                                                                                                                                                                              | Design fixed; E1, S1                                                                |
| SEC-8  | Low      | Design §6, §12                   | Linking could target a record the caller cannot see; property-word leads could be flooded by a spammer.                                                                                                                                                                         | Link requires record visibility and returns the shared 404 otherwise; automatic leads are capped per connection and per sender per day.                                                                                                                                                                                                                         | Built in X3 (`inbox/matching.rs` caps; link visibility in `inbox/triage.rs`)        |
| SEC-9  | Low      | `crypto.rs`                      | The additional authenticated data was unambiguous in practice but not length-prefixed and omitted the key version. The Calendar vault uses no additional data, so "same primitive" meant AES-GCM only.                                                                          | Length-prefixed parts plus the key version; design wording corrected.                                                                                                                                                                                                                                                                                           | Fixed in X1                                                                         |
| SEC-10 | Low      | Design §11; X1 access            | The matrix gave the Super Admin "platform metadata" while the code refuses all access.                                                                                                                                                                                          | The matrix now says none in X1; any later platform view is a separate reviewed feature. A test covers the Super Admin on another company's workspace.                                                                                                                                                                                                           | Fixed in X1                                                                         |
| SEC-11 | Low      | Design §9                        | Immutable event triggers block the 5-year purge; anonymisation missed `contact_key`, blocks and staged payloads; backups cannot inherit purges; PostgreSQL error detail can log account IDs.                                                                                    | §9 adds a retention role, wider anonymisation, documented backup expiry and `log_parameter_max_length_on_error = 0` in hosted settings.                                                                                                                                                                                                                         | Design fixed; X3 and deployment                                                     |

TikTok (added 2026-10-20 after this review) follows the same rules: SEC-1 account ownership from the token, SEC-4 signature verification confirmed against TikTok's current documentation before intake, and the social reply grant. It is reviewed again with packet T1.

## X1 code findings

| ID  | Finding                                                                                                           | Resolution                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| K1  | The account-uniqueness index covered disconnected rows, so a disconnected account could never be connected again. | Migration `0032` makes it partial (`state <> 'disconnected'`); API test connects again from the same and another company. |
| K2  | A missing `CRM_MESSAGING_KEY` silently disabled channels everywhere.                                              | Startup fails outside local development; locally the API prints a warning and Channels answers 503.                       |
| K3  | Credentials were trimmed before sealing, changing the secret.                                                     | Leading or trailing spaces are refused; API test.                                                                         |
| K4  | Account IDs of four characters or fewer were shown in full; for email the hint was only the domain ending.        | Fully masked under eight characters.                                                                                      |
| K5  | Reconnect sealed any credential without asking the provider adapter.                                              | Reconnect calls the adapter's `verify` for the stored account.                                                            |

## Checked without findings

Origin and CSRF are enforced on every write including `DELETE` with a body. Foreign or missing workspaces share one 403 and foreign or malformed connection IDs share one 404. Live membership is re-checked under the workspace lock. The sealed credential is never selected by any read. API errors never carry database detail. The credential field is write-only and never prefilled.

## X2 code review (2026-10-20)

A separate security review of the X2 code (webhook intake, the outbox and the messaging worker) found nothing High. All findings except S7 were fixed before commit.

| ID    | Severity   | Finding                                                                                                                               | Resolution                                                                                                                                              |
| ----- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| X2-S1 | Medium     | The stub signed only the body, so a captured body could be replayed with fresh event IDs, bypassing deduplication and filling tables. | The stub signs `<event ID>.<body>`. Real adapters must take the deduplication key only from signed material. API test.                                  |
| X2-S2 | Medium     | Receipts deduplicated on `(provider, event_id)`, so one company's event ID could suppress another company's event.                    | Migration 0036: unique per `(connection_id, event_id)`. API test with two companies.                                                                    |
| X2-S3 | Low/Medium | The attempt insert did not lock the job row, leaving a narrow race with the lease sweep after a ~60-second stall.                     | The insert's `SELECT` takes `FOR UPDATE`, so the lease check is re-evaluated after any sweep commits.                                                   |
| X2-S4 | Low        | The inbound sink had no time limit, so a slow sink could outlive its lease and be processed twice.                                    | `SINK_TIMEOUT` (30 s) inside the 60-second lease; a timeout is a retry.                                                                                 |
| X2-S5 | Low        | A crash on the last attempt (or a missing staging row) left the sealed body for 30 days.                                              | An exhaustion sweep marks such receipts `failed` (`attempts_exhausted`) and deletes the body. Database test.                                            |
| X2-S6 | Low        | A sink failure code that fails the column check would make settling error repeatedly.                                                 | Codes are checked and fall back to `sink_failed`. Unit test.                                                                                            |
| X2-S7 | Low        | Design §7.5 promises a counter for refused requests; none exists. After the 30-day receipt purge, a replayed body verifies as new.    | Open, carried to W2: add the refusal counter with hosting metrics, and an event-age limit shorter than retention for Twilio (which signs no timestamp). |
| X2-S8 | Low        | No test showed the stub is unreachable on a hosted server.                                                                            | The gate is a pure function with a unit test.                                                                                                           |

For X3: `outbox::enqueue` allows a new job for an object whose previous job ended `unknown`. The Inbox must refuse that unless a person explicitly chooses **Send again** (SEC-2).

## X3 Inbox review (2026-10-20)

A separate security review of the Inbox (X3a intake, X3b staff API, X3c triage and rules) found nothing High. All findings were fixed before the X3c commit.

| ID    | Severity | Finding                                                                                                                                        | Resolution                                                                                                                                                                                                                                        |
| ----- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| X3-S1 | Medium   | SEC-8's cap on automatic leads was missing; new threads from one social sender, or a flood of marked sources, could create a Client each time. | A known sender's new thread rejoins their earlier linked record; automatic leads are capped at 1 per sender and 50 per connected account per day, after which the message is a suggestion (`inbox/matching.rs`). Database tests. SEC-8 is closed. |
| X3-S2 | Low      | List and read returned a linked record's ID to viewers who cannot see that record.                                                             | The ID is returned only when `records::lookup::visible` allows it. API test.                                                                                                                                                                      |
| X3-S3 | Low      | Staff could create a duplicate lead when several records match the sender.                                                                     | Refused with 409 unless the caller is the Admin; staff link the right record instead. API test.                                                                                                                                                   |
| X3-S4 | Low      | Notes and read marks checked live membership without the workspace lock.                                                                       | Both take the lock first.                                                                                                                                                                                                                         |
| X3-S5 | Low      | Automatic leads name the company owner as their creator in the records history.                                                                | Documented: the owner is the actor of record; the Inbox event has no actor, marking it system-created.                                                                                                                                            |
| X3-S6 | Low      | Every intake failure was retried; untrusted names could carry control characters into records and exports.                                     | Refusals are permanent (`intake_refused`); control characters are stripped from parsed provider text.                                                                                                                                             |
| X3-S7 | Low      | Blocked conversations could be resolved or reopened while the block stayed; design §3's per-record unique index was not built.                 | Resolve, reopen and a second block are refused with 409 until the Admin unblocks. The index is dropped by design: one conversation per provider thread (see §3 note in the design).                                                               |
| X3-S8 | Low      | Test gaps: no Clients create grant, the Super Admin on every action, several matches, and the cap.                                             | `tests/api/inbox-guards.test.mjs` and `inbox/intake_state_tests.rs`.                                                                                                                                                                              |
